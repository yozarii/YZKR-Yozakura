# kaika Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, in this session). Steps use checkbox syntax.

**Goal:** A working `kaika` Rust CLI that installs, uninstalls, upgrades, lists, searches and inspects packages across brew, cask, npm, uv, mas and verified vendor-site downloads, with a Python resolver PoC for the decision layer.

**Architecture:** One Rust package (`kaika/`) with a library (backends, manifest, plan, verify, recipes, resolver client) and a thin binary. External tools run through a `Runner` so tests substitute stub executables. The resolver is a Python subprocess speaking JSON on stdin/stdout.

**Tech Stack:** Rust 1.100 (clap, serde, serde_json, toml, anyhow, sha2; dev: assert_cmd, tempfile); Python 3 stdlib only for the PoC; `curl`, `codesign`, `spctl`, `ditto`, `hdiutil` as system tools.

**Spec:** `docs/superpowers/specs/2026-11-21-kaika-design.md`

## Global Constraints

- Flags use established meanings: `-n/--dry-run`, `-y/--yes`, `-f/--force`, `--all`, `--zap`, `-q`, `-v`, `--json`. `--force` overrides safety only.
- Exit codes: 0 ok, 1 failure, 2 usage, 3 verification failed, 4 needs confirmation but no terminal.
- Paths: config `~/.config/kaika`, data `~/.local/share/kaika`, cache `~/.cache/kaika`; overridable with `KAIKA_CONFIG_DIR`, `KAIKA_DATA_DIR`, `KAIKA_CACHE_DIR`; apps dir `/Applications` overridable with `KAIKA_APPS_DIR`.
- Downloads are HTTPS only. `file://` is allowed only when `KAIKA_TEST_MODE=1`.
- A model returns only a candidate ID or `none`; it never supplies URLs, commands or paths.
- Tests never touch the real machine: temp HOME and dirs, stub executables first on PATH, no apps launched, no windows, no sudo, no real Ollama.

## Review Focus

- Unknown name found in no backend: exit 1, clear message, nothing changed.
- Two backends carry the name: preference order decides; `source:name` forces.
- No terminal and no `-y`: plan printed, exit 4, nothing changed.
- Failed verification with `-f`: proceeds, and the plan says so; without `-f`: exit 3.
- Resolver missing, crashing, or answering with an ID not in the candidate list: treated as unsure, escalates, then asks; never installs.

## File structure (`kaika/`)

- `src/main.rs` entry; `src/cli.rs` clap definitions; `src/commands.rs` command handlers
- `src/paths.rs` dirs; `src/runner.rs` `Runner` trait; `src/manifest.rs` state
- `src/backend/{mod,brew,cask,npm,uv,mas,direct}.rs` adapters; `src/select.rs` backend choice
- `src/plan.rs` plan model, confirm flow; `src/verify.rs` signature, notarization, Team ID, checksum
- `src/recipe.rs` recipes; `src/resolver.rs` resolver client and escalation
- `recipes/*.toml` curated recipes; `poc/resolver.py` decision layer; `poc/tests/`; `tests/` Rust integration tests with `tests/stubs/`

### Task 1: paths, runner, manifest
**Produces:** `paths::Dirs::from_env() -> Dirs{config,data,cache,apps}`; `trait Runner { fn run(&self, argv:&[String]) -> Result<Output> }` with `RealRunner`; `Manifest::{load(&Dirs), save(&self), upsert(Entry), remove(&str,&str), get(&str,&str)}` where `Entry{name,source,version,path,update_source,resolved_by,installed_at}`.
- [ ] Tests: env overrides win over XDG over HOME; manifest round-trips; upsert replaces same (source,name); missing file loads empty.
- [ ] Implement; run `cargo test`; commit.

### Task 2: backends and selection
**Produces:** `trait Backend { id; available(r); installed(r)->Vec<Pkg>; search(r,q)->Vec<Candidate>; install_argv(name); uninstall_argv(name,zap); upgrade_argv(Option<&str>); outdated(r) }`; `select::choose(name, &[Candidate], order:&[&str]) -> Choice{Chosen(Candidate)|Ambiguous(Vec)|None}`.
- [ ] Tests (recorded outputs): parse `brew leaves`/`brew list --cask --versions`, `npm ls -g --json`, `uv tool list`, `mas list`, `brew search`; `choose` honours the preference order and explicit `source:name`.
- [ ] Implement; commit.

### Task 3: plan, CLI, commands
**Produces:** `Plan{title, steps:Vec<Step>, warnings:Vec<String>}`; `confirm(plan, yes, is_tty) -> Decision`; commands `install, uninstall, upgrade, update, list, search, info, outdated, doctor, cleanup, config`.
- [ ] Integration tests with stub `brew`/`npm`/`uv`/`mas` on PATH: dry-run prints plan and changes nothing; no tty and no `-y` exits 4; `-y` runs the stub and records the manifest; uninstall `--zap` passes `--zap`; `list --json` merges live and manifest; unknown name exits 1.
- [ ] Implement; commit.

### Task 4: verification, recipes, direct backend
**Produces:** `verify::check(r, app_or_pkg, expect:&Expect) -> Report{signature,notarized,team_id,checksum, failures}`; `Recipe{name,domain,team_id,source:Github|Appcast|Page,asset_pattern}`; `direct::install(...)`.
- [ ] Tests with stub `codesign`/`spctl` and a fixture zip served via `file://` (test mode): good fixture installs into `KAIKA_APPS_DIR` and records; wrong Team ID exits 3; `-f` overrides and prints the failure; checksum mismatch exits 3; non-HTTPS URL refused outside test mode.
- [ ] Implement (curl for fetch, ditto for zip/dmg copy, hdiutil `-nobrowse -quiet` for dmg); commit.

### Task 5: resolver and escalation
**Produces:** JSON protocol `{task, query, candidates:[{id,text}], threshold}` → `{choice:id|null, confidence, evidence, model}`; `resolver::decide(...) -> Outcome{Picked(id)|Unsure}`; escalation order small model, large model, user.
- [ ] Python tests (unittest, fake Ollama server on an ephemeral port): valid ID accepted; ID outside candidates rejected; low confidence reports unsure; Ollama unreachable falls back to heuristic scoring; prompt-injection text in a candidate cannot change the answer shape.
- [ ] Rust tests with a stub resolver script: crash, bad JSON, foreign ID all yield `Unsure`.
- [ ] Implement; commit.
